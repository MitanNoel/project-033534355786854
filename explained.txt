    |   ├── evaluator.py        (Model evaluation)
    |   └── predictor.py        (Making predictions)
    |

    |   └── SCENARIOS dictionary (4 preprocessing/training configurations)
    |
    +-- Persistent Storage
        ├── models/             (Trained models, vectorizers)
        ├── uploads/            (Uploaded CSV files)
        └── logs/               (Experiment results)


WORKFLOW TIMELINE:
-----------------

Step 1: User Upload CSV
    app.py (/upload)
    -> validate_csv()
    -> session['uploaded_file'] stored

Step 2: Data Quality Check
    check_data_quality()
    -> Label distribution shown
    -> Warnings if issues detected

Step 3: Choose Preprocessing
    User selects preprocessing level
    -> Session stores which preprocessing steps to apply

Step 4: Start Training
    app.py calls train_all_scenarios()
    -> For each scenario: preprocess -> vectorize -> split -> train 2 models
    -> Results: 8 trained models saved to disk

Step 5: Evaluate All Models
    evaluate_all_scenarios()
    -> Calculate metrics for all 8 models
    -> Select best model based on F1-Score
    -> Save metadata of best model

Step 6: Make Predictions
    User enters new text
    -> Load best model + vectorizer
    -> Apply same preprocessing + vectorization
    -> Model predicts emotion
    -> Show result to user

def clean_text(text):
    # Remove URLs
    text = re.sub(r'http\S+|www\S+|https\S+', '', text, flags=re.MULTILINE)

    # Remove mentions (@username)
    text = re.sub(r'@\w+', '', text)

    # Remove hashtags (#topic)
    text = re.sub(r'#\w+', '', text)

    return text
```

def get_stopwords():
    # Returns set of ~100 common English words
    return {'a', 'an', 'the', 'is', 'are', 'was', 'were', 'be', 'been',
            'have', 'has', 'had', 'do', 'does', 'did', 'and', 'or', 'but',
            'of', 'at', 'by', 'for', 'with', 'to', 'from', 'in', 'on', ...}

def remove_stopwords(text):
    stopwords = get_stopwords()
    words = text.split()
    filtered = [w for w in words if w not in stopwords]
    return ' '.join(filtered)
```

Input:  "aku sangat bahagia sekali 🎉 kata"
Output: "sangat bahagia sekali kata"
        (assuming 'aku', 'dan', 'yang', etc. in stopwords)

Why: Words like "the", "is", "and" appear in every text, don't help distinguish emotions

NOTE: Current implementation uses English stopwords. Better approach would use
Indonesian stopwords list for more accurate filtering.


STEP 6: apply_stemming() (lines 103-111)
-------
Purpose: Reduce inflected words to root form

Code:
```
from nltk.stem import PorterStemmer

stemmer = PorterStemmer()  # English stemmer

def apply_stemming(text):
    words = text.split()
    stemmed = [stemmer.stem(w) for w in words]
    return ' '.join(stemmed)
```

Example transformations:
- "bahagia" -> "bahagi" (removes suffix -a)
- "berlari" -> "ber" (removes suffix -lari)
- "marah" -> "marah" (already root)

Input:  "sangat bahagia sekali kata"
Output: "sangat bahagi sekali kata"

Why: "bahagia" and "kebahagiaan" should both map to same root

NOTE: Porter Stemmer is for English words. Indonesian uses different morphology.
Ideal tool would be Sastrawi library (Indonesian stemmer).

```
def preprocess_texts(texts, config, show_progress=True):
    """
    Preprocess multiple texts according to configuration

    Args:
        texts: List of text strings
        config: Configuration dict with preprocessing flags
        show_progress: Show progress bar

    Returns:
        List of preprocessed texts
    """
    processed = []
    total = len(texts)

    for idx, text in enumerate(texts):
        # Start with basic cleaning
        result = clean_text(text)

        # Apply optional steps based on config
        if config.get('lowercase', True):
            result = to_lowercase(result)

        if config.get('remove_punctuation', True):
            result = remove_punctuation(result)

        if config.get('remove_numbers', True):
            result = remove_numbers(result)

        if config.get('remove_stopwords', False):  # Default False
            result = remove_stopwords(result)

        if config.get('stemming', False):  # Default False
            result = apply_stemming(result)

        processed.append(result)

        # Show progress
        if show_progress and (idx + 1) % 500 == 0:
            print(f"Preprocessing: {idx + 1}/{total} texts")

    return processed
```

How it's called from app.py:

```

    texts,
    preprocessing_config,
    show_progress=True
)
# Returns list of cleaned texts
```

File: src/feature_extractor.py

After preprocessing, text is still strings. Machine learning models need numbers.
Feature extraction converts text --> numeric vectors (arrays of numbers).

THE PROBLEM:
-----------
ML models work with numbers, not text. We need to convert:

Text:           "sangat bahagia"
What we need:   [0.5, 0.3, 0.0, 0.2, ...]  (array of 5000 numbers)


THE SOLUTION: TF-IDF VECTORIZATION
-----------------------------------

Step 1: Build Vocabulary
--------
Process all training texts and create dictionary of unique words:

Texts:
- "sangat bahagia"
- "marah sekali"
- "sedih"
- "takut sekali"

Vocabulary (word -> ID):
{
  'sangat': 0,
  'bahagia': 1,
  'marah': 2,
  'sekali': 3,
  'sedih': 4,
  'takut': 5
}

Code from feature_extractor.py (lines 5-32):
```
from sklearn.feature_extraction.text import TfidfVectorizer

def create_vectorizer(method='tfidf', max_features=5000, ngram_range=(1, 2)):
    if method == 'tfidf':
        return TfidfVectorizer(
            max_features=max_features,  # Keep only top 5000 words
            ngram_range=ngram_range,     # 1-word and 2-word phrases
            min_df=2,                    # Ignore words appearing < 2 docs
            max_df=0.95                  # Ignore words appearing > 95% docs
        )
```

Parameters explained:
- max_features=5000: Keep only 5000 most important words (ignore rare words)
- min_df=2: Word must appear in at least 2 documents (avoid one-off typos)
- max_df=0.95: Word appearing in > 95% docs is too common (filtered out)
- ngram_range=(1,2): Create features for 1-word and 2-word combinations


Step 2: Calculate TF-IDF Scores
-------

TF-IDF = Term Frequency - Inverse Document Frequency

Formula:
TF-IDF(word, document) = TF(word, document) × IDF(word)

Where:
  TF(word, doc) = frequency of word in document / total words in document
  IDF(word) = log(total documents / documents containing word)

Example:
Text 1 (happy): "sangat bahagia"
- TF('sangat'): 1/2 = 0.5 (appears 1 time out of 2 words)
- TF('bahagia'): 1/2 = 0.5

Corpus statistics (100 documents total):
- 'sangat' appears in 50 documents -> IDF = log(100/50) = 0.30
- 'bahagia' appears in 20 documents -> IDF = log(100/20) = 0.70

TF-IDF scores:
- TF-IDF('sangat') = 0.5 × 0.30 = 0.15
- TF-IDF('bahagia') = 0.5 × 0.70 = 0.35

Why TF-IDF instead of raw count?
- 'bahagia' (happy word) gets higher score even though both appear once
- Words appearing in many documents (common stopwords) get lower weight
- Balances frequency and relevance


Step 3: Create Feature Vectors
------

Text: "sangat bahagia"

Feature vector (sparse, only non-zero values shown):
Index: [0, 1, 2, 3, 4, 5, ...]
Value: [0.15, 0.35, 0, 0, 0, 0, ...]
       (sangat, bahagia, marah, sekali, sedih, takut, ...)

Code from feature_extractor.py (lines 34-49):
```
def fit_transform_features(texts, method='tfidf', max_features=5000, ngram_range=(1,2)):
    vectorizer = create_vectorizer(method, max_features, ngram_range)
    features = vectorizer.fit_transform(texts)
    return features, vectorizer
```

For 4401 training texts:
features shape = (4401, 5000)
- 4401 rows (one per text)
- 5000 columns (one per word in vocabulary)

Matrix is "sparse": Most values are 0 (text doesn't contain most words)
scikit-learn stores only non-zero values in memory (efficient)


UNIGRAM vs BIGRAM vs TRIGRAM:
-----------------------------

Unigram (1-word):
Vocabulary: ['sangat', 'bahagia', 'marah', 'sekali', ...]
Features: Single words only
Max Features: 3000 (Scenario 1)

Example text: "sangat bahagia"
Features: [sangat=0.5, bahagia=0.5, ...]


Bigram (2-word):
Vocabulary: ['sangat', 'bahagia', 'sangat bahagia', 'marah sekali', ...]
Features: Single words + two-word phrases
Max Features: 5000 (Scenario 2)

Example text: "sangat bahagia"
Features: [sangat=0.3, bahagia=0.3, 'sangat bahagia'=0.4, ...]

Benefit: Captures context! "sangat bahagia" (very happy) is different from
just "bahagia" (happy)


Trigram (3-word):
Vocabulary includes 3-word phrases
Max Features: 7000 (Scenario 4)

Example: "sangat sekali bahagia" captures 3-word emotions
But: Rarer in training set, can cause overfitting


Why Scenario 2 (Bigram) is Best:
- Unigram (Scenario 1): Loses context "sangat bahagia" vs just "bahagia"
- Bigram (Scenario 2): Captures useful context with 5000 features (good balance)
- Trigram (Scenario 4): Too sparse, specific phrases appear rarely


COUNT VECTORIZER vs TF-IDF:
---------------------------

Count Vectorizer (Scenario 3):
- Produces raw word counts
- Text "sangat sangat bahagia" -> 'sangat'=2, 'bahagia'=1
- Doesn't weight by document frequency
- Problem: Common words (stopwords we didn't remove) get high counts

Code:
```
from sklearn.feature_extraction.text import CountVectorizer

count_vectorizer = CountVectorizer(max_features=5000, ngram_range=(1,2))
```

TF-IDF Vectorizer (Scenario 2):
- Produces weighted scores (TF-IDF formula)
- Same text "sangat sangat bahagia" -> normalized and weighted
- Common words get lower weight, emotion words higher weight
- Better for classification

Result: TF-IDF (Scenario 2) outperforms Count Vectorizer (Scenario 3)
by ~3.5% F1-Score (0.6552 vs 0.6204)

def save_vectorizer(vectorizer, filepath):
    """Save vectorizer to file"""
    os.makedirs(os.path.dirname(filepath), exist_ok=True)
    joblib.dump(vectorizer, filepath)

def load_vectorizer(filepath):
    """Load vectorizer from file"""
    try:
        vectorizer = joblib.load(filepath)
        return vectorizer
    except Exception as e:
        print(f"Error loading vectorizer: {e}")
        return None
```

Critical Point: MUST use same vectorizer for training and prediction!

Training phase:

If you use different vectorizer, word mappings are different -> wrong predictions!

PART 5: MODEL TRAINING - ALGORITHMS EXPLAINED
================================================================================

File: src/model_trainer.py

After converting text to numeric vectors, machine learning models learn to
classify emotions. Two algorithms are used: Naive Bayes and SVM.


ALGORITHM 1: NAIVE BAYES MULTINOMIAL
====================================

Theory:
-------
Naive Bayes uses probability and Bayes' theorem to predict emotion.

Formula:
P(emotion | features) = P(features | emotion) × P(emotion) / P(features)

Where:
- P(emotion | features) = Probability emotion given text (what we want)
- P(features | emotion) = Probability features given emotion (from training)
- P(emotion) = How common each emotion in training set
- P(features) = Probability of features (normalizing constant)

Key assumption: Word frequencies are independent (naive assumption, not always true)

Code from model_trainer.py (lines 11-25):
```
from sklearn.naive_bayes import MultinomialNB

def train_naive_bayes(X_train, y_train, alpha=1.0):
    """Train Multinomial Naive Bayes classifier"""
    model = MultinomialNB(alpha=alpha)
    model.fit(X_train, y_train)
    return model
```

Training process:
Input: X_train (3520 × 5000 features), y_train (3520 labels)
Model learns: For each emotion, distribution of word frequencies
Output: Trained model with probability tables


DETAILED EXAMPLE:
-----------------

Training set emotions:
- happy: 800 texts
- anger: 900 texts
- sadness: 850 texts
- fear: 600 texts
- love: 370 texts
Total: 3520 texts

Naive Bayes learns probabilities:

P(emotion):
- P(happy) = 800 / 3520 = 0.227
- P(anger) = 900 / 3520 = 0.256
- P(sadness) = 850 / 3520 = 0.242
- P(fear) = 600 / 3520 = 0.170
- P(love) = 370 / 3520 = 0.105

P(word | emotion):
For each word in vocabulary, count how often it appears in each emotion:

Word 'bahagia' (happy):
- Appears in 200 happy texts out of 800
- P(bahagia | happy) = 200 / 800 = 0.25

Word 'bahagia' in anger:
- Appears in 20 anger texts out of 900
- P(bahagia | anger) = 20 / 900 = 0.022

Word 'bahagia' in all emotions much less frequent


PREDICTION PROCESS:
-------------------

New text: "sangat bahagia"
Features: [sangat=0.15, bahagia=0.35, others=0]

Calculate probability for each emotion:

P(happy | text) ∝ P(sangat | happy) × P(bahagia | happy) × P(happy)
                = 0.10 × 0.25 × 0.227
                = 0.00568

P(anger | text) ∝ P(sangat | anger) × P(bahagia | anger) × P(anger)
               = 0.08 × 0.022 × 0.256
               = 0.000447

P(sadness | text) ∝ P(sangat | sadness) × P(bahagia | sadness) × P(sadness)
                  = 0.09 × 0.018 × 0.242
                  = 0.000392

P(fear | text) ∝ P(sangat | fear) × P(bahagia | fear) × P(fear)
              = 0.07 × 0.010 × 0.170
              = 0.000119

P(love | text) ∝ P(sangat | love) × P(bahagia | love) × P(love)
              = 0.09 × 0.020 × 0.105
              = 0.000189

Highest probability: P(happy) ≈ 0.00568
Prediction: HAPPY ✓


ALPHA PARAMETER (SMOOTHING):
---------------------------

Problem: If word never appears in training emotion, P(word | emotion) = 0
This makes entire probability = 0 (incorrect)

Solution: Laplace smoothing with alpha parameter

Without smoothing:
P(word | emotion) = count(word in emotion) / total_words_in_emotion

With smoothing:
P(word | emotion) = (count + alpha) / (total_words + alpha × vocabulary_size)

Example:
- 'bahagia' never appeared in anger texts: count = 0
- Without smoothing: P(bahagia | anger) = 0 / 900 = 0 (problem!)
- With alpha = 1.0: P(bahagia | anger) = (0 + 1) / (900 + 1×5000) = 0.0002

effect of alpha values:
- alpha = 0: No smoothing (can cause 0 probabilities)
- alpha = 0.5: Moderate smoothing (Scenario 2 uses this)
- alpha = 1.0: Strong smoothing (Scenario 1, 3 use this)
- alpha = 0.1: Aggressive smoothing (Scenario 4 uses this, risks overfitting)

Why Scenario 2 uses alpha = 0.5:
- Already did aggressive preprocessing (removed stopwords, stemmed)
- Needs moderate smoothing to generalize well


ALGORITHM 2: SUPPORT VECTOR MACHINE (SVM)
==========================================

Theory:
-------
SVM finds a hyperplane (decision boundary) that maximally separates emotions
in feature space.

2D visualization (simplified):

Feature space with 2 words: 'sangat' (x-axis) and 'marah' (y-axis)

      | sadness
      |
      |     happiness
------|---------------  decision boundary
      |
      | anger
      |
      +------------------

Goal: Find line (hyperplane in high dimensions) maximizing margin between classes

Code from model_trainer.py (lines 27-43):
```
from sklearn.svm import LinearSVC

def train_svm(X_train, y_train, C=1.0, kernel='linear', max_iter=1000):
    """Train SVM classifier"""
    model = LinearSVC(C=C, max_iter=max_iter, random_state=Config.RANDOM_STATE)
    model.fit(X_train, y_train)
    return model
```

Parameters:
- C: Regularization parameter (tradeoff between margin and misclassification)
- max_iter: Maximum iterations for optimization
- kernel: Type of decision boundary (linear, rbf, etc.)


C PARAMETER (REGULARIZATION):
----------------------------

C controls strictness of the margin:

C = 0.1 (very lenient):
- Model tolerates more misclassifications
- Simpler decision boundary
- Risk of underfitting

C = 1.0 (balanced) - Scenario 1, 2, 3 use this:
- Balances margin and errors
- Good generalization

C = 10.0 (strict) - Scenario 4 uses this:
- Model punishes misclassifications heavily
- Complex decision boundary
- Risk of overfitting

Why Scenario 4 overfits with C=10.0:
- Also uses trigram features (7000 features, very sparse)
- Aggressive C value forces model to memorize training data
- Doesn't generalize to test data
- Result: F1-Score drops to 0.6172 (lower than Scenario 2's 0.6552)


TRAINING PROCESS:
-----------------

Code execution from model_trainer.py:

1. Prepare training data:
   X_train shape: (3520, 5000)  # 3520 texts, 5000 features
   y_train shape: (3520,)       # 3520 labels (happy, anger, etc.)

2. Create and train model:
   model = LinearSVC(C=1.0, max_iter=500, random_state=42)
   model.fit(X_train, y_train)

3. SVM optimization problem solved:
   Minimize: (1/2) × ||w||^2 + C × Σ(errors)

   Where:
   - w = weight vector (direction of decision boundary)
   - errors = misclassifications on training set
   - C = how much to penalize errors

4. Model learns:
   - Weight vector w (which features matter)
   - Bias term b (intercept)

5. Save model:
   joblib.dump(model, 'models/scenario_2_svm.joblib')
   Model is ready for predictions


PREDICTION WITH SVM:
-------------------

New text: "sangat bahagia"
Features: [0.15, 0.35, 0, 0, ...]

Linear decision function:
score_emotion = w · features + b

Example learned weights:
- happy class: w_happy = [0.5, 0.6, -0.1, 0.1, ...]
               score_happy = 0.5×0.15 + 0.6×0.35 + ... = 0.275

- anger class: w_anger = [-0.4, -0.5, 0.3, 0.2, ...]
              score_anger = -0.4×0.15 + -0.5×0.35 + ... = -0.235

All emotions calculated similarly

Highest score: happy (0.275)
Prediction: HAPPY ✓


WHY SVM > NAIVE BAYES (Performance):
-----------------------------------

Results from experiment:
- Scenario 1: NB=0.6051, SVM=0.6509 (+0.0458)
- Scenario 2: NB=0.6236, SVM=0.6552 (+0.0316)
- Scenario 3: NB=0.6187, SVM=0.6204 (+0.0017)
- Scenario 4: NB=0.5887, SVM=0.6172 (+0.0285)

Reasons:
1. Naive Bayes assumes feature independence (not true for words)
   - "sangat bahagia" features are correlated
   - SVM doesn't make this assumption

2. SVM finds complex decision boundaries (through hyperplane)
   - More flexible than probability-based approach
   - Can capture non-linear patterns better

3. SVM optimizes margin (separation between classes)
   - Focuses on hard-to-classify examples
   - Better generalization

4. TF-IDF features work better with SVM
   - Dimensionality advantage (5000 dimensions)
   - SVM performs well in high dimensions


TRADE-OFFS:
-----------

Naive Bayes advantages:
- Very fast training (linear time)
- Works well with small datasets
- Interpretable probability outputs
- Lower memory requirement

SVM advantages:
- Better accuracy on complex data
- Handles high-dimensional features well
- Robust to outliers
- Good generalization

SVM disadvantages:
- Slower training (quadratic time)
- Harder to interpret (just scores)
- Requires hyperparameter tuning (C value)

For this project: SVM wins because sentiment has complex patterns

File: src/evaluator.py

After training 8 models, evaluate which performs best.

THE PROBLEM:
-----------
How do we know which model is best? Need metrics to compare.

FOUR EVALUATION METRICS:
------------------------

For each model on test set (881 test samples), calculate:

1. ACCURACY
   Formula: Accuracy = (TP + TN) / (TP + TN + FP + FN)

   Translation: How many predictions were correct?

   Example:
   - Correct predictions: 565
   - Total predictions: 881
   Accuracy = 565 / 881 = 0.6413 (64.13%)

   Interpretation: 64.13% of predictions were right

   Code:
   ```
   from sklearn.metrics import accuracy_score
   accuracy = accuracy_score(y_test, predictions)
   ```

   Problem: Doesn't work well with imbalanced classes
   - If you predict everything as "happy" in imbalanced dataset, accuracy looks good

   Use when: Classes are balanced


2. PRECISION
   Formula: Precision = TP / (TP + FP)

   Translation: Of the texts you predicted as emotion X, how many were correct?

   Example for 'happy' emotion:
   - Predicted as happy: 300
   - Actually happy: 200
   - Precision = 200 / 300 = 0.667 (66.7%)

   Interpretation: When model says "happy", it's right 66.7% of the time

   Code:
   ```
   from sklearn.metrics import precision_score
   precision = precision_score(y_test, predictions, average='weighted')
   # 'weighted' = average across all classes, weighted by support
   ```

   Use when: You want to minimize false positives (false alarms)


3. RECALL
   Formula: Recall = TP / (TP + FN)

   Translation: Of texts actually emotion X, how many did you find?

   Example for 'anger' emotion:
   - Actually angry: 220
   - Detected as angry: 162
   - Recall = 162 / 220 = 0.736 (73.6%)

   Interpretation: Catch 73.6% of actual angry texts

   Code:
   ```
   from sklearn.metrics import recall_score
   recall = recall_score(y_test, predictions, average='weighted')
   ```

   Use when: You want to minimize false negatives (missing cases)


4. F1-SCORE (PRIMARY METRIC)
   Formula: F1 = 2 × (Precision × Recall) / (Precision + Recall)

   Translation: Harmonic mean of precision and recall

   Example:
   Precision = 0.668 (weighted average)
   Recall = 0.648 (weighted average)
   F1 = 2 × (0.668 × 0.648) / (0.668 + 0.648) = 0.658

   Interpretation: Balanced measure between precision and recall
   - Focuses on minority classes
   - Doesn't assume balanced dataset

   Code:
   ```
   from sklearn.metrics import f1_score
   f1 = f1_score(y_test, predictions, average='weighted')
   ```

   Why best for this project:
   - Dataset has class imbalance (fear=14.7%, love=14.5%)
   - F1-Score handles imbalance better than accuracy
   - Penalizes both false positives and false negatives

   **This is why we select best model by F1-Score**

def evaluate_model(model, X_test, y_test):
    """Evaluate single model"""
    from sklearn.metrics import accuracy_score, precision_score, recall_score, f1_score, confusion_matrix

    # Make predictions
    predictions = model.predict(X_test)

    # Calculate metrics
    metrics = {
        'accuracy': accuracy_score(y_test, predictions),
        'precision': precision_score(y_test, predictions, average='weighted', zero_division=0),
        'recall': recall_score(y_test, predictions, average='weighted', zero_division=0),
        'f1_score': f1_score(y_test, predictions, average='weighted', zero_division=0),
        'confusion_matrix': confusion_matrix(y_test, predictions),
        'per_class': classification_report(y_test, predictions, output_dict=True)
    }

    return metrics, predictions
```

    # Preprocess all at once
    processed_texts = preprocess_texts(texts, preprocessing_config)

    # Vectorize all at once
    features = transform_features(processed_texts, vectorizer)
    # (5, 5000) sparse matrix - 5 texts, 5000 features

    # Predict all at once
    predictions = model.predict(features)
    # array(['happy', 'anger', 'sadness', 'fear', 'love'])

    return predictions
```

Main function called from app.py:

```
def predict_with_best_model(texts):
    model, vectorizer, config, metadata = load_best_model()

    if model is None:
        return None

    predictions = predict_batch(texts, model, vectorizer, config['preprocessing'])

    return predictions
```


WHY SAME PREPROCESSING IS CRITICAL:
-----------------------------------

Example of what goes wrong:

Wrong approach (using different preprocessing):
Training: No stopword removal, no stemming
Test: Removed stopwords and stemmed

Training learned:
- vocabulary includes 'aku', 'dengan', 'yang' (stopwords)
- vocabulary includes 'bahagia', 'kebahagiaan' (inflected forms)
- word 'bahagia' has weight 0.5 from learning

Test preprocesses same text differently:
- 'aku' removed (stopword removed in test, but existed in training vocab!)
- 'kebahagiaan' stemmed to 'bahagia'
- Creates features using stemmed form
- But training never saw stem form for this word!
- Feature vector completely different
- Model prediction = garbage

Correct approach (what we do):
Training preprocessing saved in config.json:
{
  'lowercase': True,
  'remove_punctuation': True,
  'remove_numbers': True,
  'remove_stopwords': True,
  'stemming': True
}

Prediction uses EXACT same config
→ Same preprocessing
→ Same feature vector
→ Correct prediction

Only difference: method='count' instead of 'tfidf'

Impact:

Why: TF-IDF weights rare-but-important words higher
     Count treats all word appearances equally

================================================================================
KEY TECHNICAL INSIGHTS
================================================================================

1. CONSISTENCY IS CRITICAL
   Training preprocessing → Test preprocessing MUST be identical
   Training vocabulary → Test vectorization MUST use same vocab
   Mismatch = garbage predictions

2. PREPROCESSING TRADEOFF
   More aggressive cleaning → Less noise but risk losing information
   Scenario 2 balances this optimally (removes common words, preserves emotion)

3. FEATURE ENGINEERING
   Text → Sparse vectors (mostly zeros)
   Bag-of-words loses order (SVM > NB because it doesn't assume independence)
   Bigram adds minimal cost for significant benefit

4. SPARSE MATRICES
   4401 samples × 5000 features = 22 million values
   If stored dense: 22M × 8 bytes = 176 MB
   Sparse storage: Only ~3% non-zero = ~5 MB (efficient!)

5. STRATIFIED SPLIT
   Preserves class distribution in train/test
   Prevents evaluation bias

6. METRICS SELECTION
   Accuracy: Good if classes balanced
   F1-Score: Good for imbalanced classes (our case)
   Use F1-Score for emotion (classes 14.5% - 25%)

7. HYPERPARAMETER BALANCE
   Too lenient (C=0.1): Underfitting
   Too strict (C=10.0): Overfitting
   Balanced (C=1.0): Optimal generalization

8. ONLINE vs BATCH PROCESSING
   Single prediction: Load model once, process single text
   Batch predictions: Load model once, process multiple texts (more efficient)

9. MODEL PERSISTENCE
   joblib.dump(): Save trained model to disk
   joblib.load(): Load model later (no retraining needed)
   Vectorizer persistence: CRITICAL for consistent vectorization

10. SESSION MANAGEMENT
    Flask session: Server-side storage
    Survives across HTTP requests
    Stores file paths, column names, user choices


================================================================================
DEBUGGING COMMON ISSUES
================================================================================

Issue 1: Wrong predictions despite good training metrics

Cause: Preprocessing mismatch
Solution:
  - Check preprocessing_config in best_model_metadata.json
  - Ensure predictor.py uses EXACT same config
  - Compare text before/after preprocessing in both training and prediction

Issue 2: Different predictions with same text

Cause: Different model loaded, or preprocessing changed
Solution:
  - Verify best_model_metadata.json points to correct model
  - Check if models were retrained (vocabulary changed)
  - Reload model from correct file

Issue 3: Very low accuracy on training data itself

Cause: Dataset too small, classes too imbalanced, or bad preprocessing
Solution:
  - Check data quality (missing values, outliers)
  - Verify label distribution
  - Try different preprocessing scenarios

Issue 4: Memory error with large CSV

Cause: File too large (> 16MB limit set in config.py)
Solution:
  - Split CSV into smaller files
  - Or increase MAX_CONTENT_LENGTH in config.py
  - Or filter data (less rows)

Issue 5: "No module named NLTK" error

Cause: NLTK not installed
Solution:
  - pip install nltk
  - Script will auto-download stopwords

Issue 6: Model won't load

Cause: File corrupted or wrong path
Solution:
  - Check file exists: ls -la models/best_model_metadata.json
  - Verify path in metadata.json matches actual files
  - Retrain models (creates fresh files)
